# Workflow graduation release procedure

Scope: only Penghou.Workflow.Abstractions. The historical workflow-package-release-handoff is the preview checkpoint, superseded for graduation by the stable contract and this procedure. The existing Transport publisher remains the default; never dispatch it for this track.

1. Keep release worktree clean; freeze Shipped API and stable policy, commit reviewed changes.
2. Dedicated `Qualify exact Workflow graduation artifacts` workflow can be dispatched without publication on the selected branch. It packs once from exact github.sha, validates against public preview.2 API and all target TFMs, retains packages/hashes and runs the exact nupkg contract suite plus package-only source and unchanged-binary consumers on Windows/Linux/macOS, net8/net10.
3. `Publish selected Penghou package family to NuGet`, main, explicit `family=Workflow`: runs those same exact artifact gates, then trusted NuGet OIDC publication of the retained artifacts only. Transport jobs are skipped. Never repack in the publisher.
4. Public verification waits for indexing and compares every package payload entry with the qualified artifact (NuGet repository signature excluded). Fresh unique caches, public-only sources prove selected behavior for neutral consumers and published Zhinu 0.2.0-preview.3 SQLite/protected execution. Unchanged binaries compiled against preview.2 (RC release) or rc.1 (stable release) have their Workflow DLL replaced; consumer hashes prove no rebuild. Zhinu's published exact old pin is overridden only in the isolated compatibility test, with NU1608 acknowledged; this is compatibility evidence, not a claim its published dependency metadata adopted 1.0.
5. Require all RC exact/public gates before setting 1.0.0 and changing package validation baseline to published 1.0.0-rc.1; stable source is the same contract lineage. Run all stable gates and public verification, then tag exact source `workflow-v1.0.0`. Record run URLs, commit, package hashes, per OS/TFM results and qualification UTC timestamps in repository evidence. Future releases validate against public 1.0.0 baseline.

No authority adapter implementation is changed or executed. A conforming neutral authorizer and real published Zhinu consumer provide the permitted boundary proof; optional Hufu adapter remains excluded security work. No restart claim is made for a dependency-free value package. Public proof is not production-host authority certification.
